01 / THE EXCHANGE

One shared exchange, many independent actors

Who actually talks to kube-apiserver?

kubectl is one client. Controllers, scheduler, kubelets and extensions also use the Kubernetes API to observe or change cluster state. etcd sits behind the API server as durable backing state.

Context: Special API-server-initiated and external-provider calls exist; ordinary application traffic is a different path.

02 / THE EXCHANGE

A request must pass the right gates before state changes

Where can an API request stop before an object is stored?

Authentication identifies the caller. Authorization evaluates this operation. Applicable admission can mutate or reject an object-changing request before persistence.

Context: The rail is conceptual; ordinary GET/LIST/WATCH bypass admission.

03 / THE EXCHANGE

Controllers follow API changes instead of hammering etcd

How does a controller learn that a Deployment changed?

LIST establishes initial state and a resourceVersion. WATCH streams later changes. Client informers and server caches mean a logical decision need not fetch every object directly from etcd.

Context: A too-old watch can require a new LIST after 410 Gone.

04 / RECONCILIATION

Objects persist; reconcilers repair relationships

Why does deleting a managed Pod make another Pod appear?

Deployment, ReplicaSet and Pod are separate API objects linked by selectors and owner references. Each controller compares its slice of observed state with desired state and may decide that no write is needed.

Context: A container restart keeps the same Pod identity. Pod deletion or loss is a different recovery path.

06 / RECONCILIATION

A Pod passes several independent boundaries before it serves traffic

Why can a Pod exist but remain Pending, Running or unready?

Scheduler explains placement from declared requests and constraints. Kubelet then handles node-local preparation, container start and probes. Readiness controls endpoint eligibility without deleting the Pod.

Context: The fixture models a small subset of scheduling and node-execution inputs so every outcome remains explainable.

08 / BOUNDARIES

The API does not carry ordinary application requests

Does HTTP traffic to web pass through kube-apiserver?

The EndpointSlice controller writes endpoint state through the API. A node service dataplane uses that state to forward application packets to Pods.

Context: kube-proxy is optional when another implementation provides Service forwarding.

Which work stops first, and which work keeps running?

A fault affects API availability, reconciliation, node execution or application traffic differently. The first detector and changed API object tell you where the loop stalled.

10 / BOUNDARIES

API replicas can serve concurrently

What happens if one API server replica fails?

A healthy control-plane endpoint can route around one failed replica. etcd and endpoint availability remain shared dependencies. Scheduler and controller-manager leadership use separate Lease coordination.

Context: Three API replicas do not imply tolerance of any two control-plane failures.

12 / INTERNALS

Kubernetes is many loops around one state gateway

Why not directly connect every component to every other one?

A common object model, policy boundary, watch semantics and durable backing state let independent actors converge without a monolithic orchestrator.

Context: This is a state-coordination model, not a claim about every network call or runtime mechanism.
