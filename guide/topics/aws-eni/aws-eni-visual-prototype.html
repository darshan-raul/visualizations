Meet ENI-123

Start with the passport. The attached service may change, but subnet-scoped network identity is the reusable primitive.

02

One interface lives in one subnet

You can create a different interface elsewhere. You cannot stretch or move this interface across subnet or AZ boundaries.

03

One EC2 instance, two networks

Multiple attachments let one guest participate in multiple subnets when every interface matches the instance's Availability Zone.

04

Which checkpoint blocked the packet?

flow-42: 10.20.1.17:43122 → 10.20.3.25:5432/TCP crosses controls with different jobs.

05

The primitive repeats. Ownership does not.

ENI-123 is now a teaching persona, not one literal interface hopping between services.

06

ECS tasks become VPC citizens

In awsvpc, each task gets addresses and security groups. On EC2 hosts, attachment density becomes scheduling capacity.

07

EKS Pods spend ENI capacity

The VPC CNI turns address or prefix slots into Pod addresses. Selected Pods may use branch ENIs for Pod security groups.

08

1,000 invocations do not mean 1,000 ENIs

Lambda shares managed Hyperplane networking for compatible subnet and security-group combinations.

09

Sometimes the interface sits on the route

An EC2 firewall needs both the AWS-side source/destination check and guest routing configured for forwarding.

10

Network identity can outlive compute

A secondary ENI can move between instances in the same AZ. That is a useful failover primitive—not multi-AZ HA.

11

Networking is application capacity

Scale can stop at address space, attachments, address/prefix slots, or branch capacity while compute remains free.

12

Follow the interface, then the packet

Resolve each workload to a network identity, then gather evidence at each checkpoint instead of changing every rule at once.

13

ENI is not ENA is not EFA

The similar names answer different questions: VPC identity, ordinary high-performance IP networking, and tightly coupled compute fabric.

14

Now find the interfaces everywhere

The final map recombines the mental model. Highlight one concern at a time.

  1. Place it
    VPC, AZ, subnet.
  2. Address it
    IPv4, IPv6, prefixes.
  3. Secure it
    SG and NACL by scope.
  4. Route it
    Forward and return path.
  5. Own it
    Know lifecycle control.
  6. Scale it
    Budget IP and ENI slots.
  7. Observe it
    Flow Logs and signals.
  8. Fail it
    Test routes and exhaustion.
  9. Refine it
    Remove complexity.
