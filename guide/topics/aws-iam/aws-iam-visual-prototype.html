Where other paths enter

IAM-user access keys enter at signing. EC2 and other workload credential providers enter at the temporary-credential stage. Direct SAML/OIDC federation uses a different STS API to create the session. Anonymous requests to supported public resources have no signed principal.

Users & roles

An IAM user is an account identity that can have a password and long-term access keys. A role has trust and permission configuration, but no standard long-term access keys. STS issues credentials for a session of that role.

Relationships, not execution order. Resource policies can grant or deny. An absent optional boundary or session policy adds no limit. RCPs, endpoint policies, KMS checks, and service-specific rules may also apply.

Role ARN, session ARN, and cross-account exceptions

A same-account resource grant directly to a role-session ARN is not limited by implicit denies in identity, boundary, or session policies. Grants to the role ARN remain limited by boundary and session policy. Applicable explicit denies and Organizations controls still matter. A direct external-account resource request requires authorization on both sides; this lab models an S3 request after assuming a role in the resource account.
