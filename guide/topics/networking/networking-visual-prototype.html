01 / FOLLOW THE REQUEST

One request crosses several decision points

What happens after an application asks for app.example.test?

DNS supplies an address before TCP begins. The client then selects a route and a next-hop link address; routers repeat forwarding decisions at each hop.

Boundary: The diagram keeps TLS and internet-provider routing outside the frame. 203.0.113.80 and 198.51.100.0/24 are documentation-only addresses.

Failure state: The resolver has no usable answer. No TCP SYN is sent because the application does not yet have a destination address.

02 / FOLLOW THE REQUEST

Each layer adds the address it owns

Which address matters to the next device, and which one identifies the final peer?

The Ethernet frame is only for the current local link. The IP packet carries the end-to-end destination, while TCP identifies the receiving transport endpoint.

Boundary: The exact link layer changes across a path. A router removes the incoming frame and builds a new frame for its outgoing link.

Failure state: The route is valid, but the host cannot resolve the gateway’s link-layer address. Local delivery waits or fails before the frame can leave.

03 / ADDRESS AND LOCAL LINK

The prefix decides what is local

Does 203.0.113.80 live on the client’s link?

The client has 10.20.10.25/24, so its directly connected subnet is 10.20.10.0/24. A destination outside it needs a route through a next hop. A prefix describes a network range, not a physical wire.

Boundary: IPv6 uses prefixes too, but its address and neighbor behavior differs. Broadcast is an IPv4 local-link concept.

Failure state: A misconfigured prefix can make the host treat a remote peer as on-link and attempt neighbor resolution instead of using the intended gateway.

04 / ADDRESS AND LOCAL LINK

The first frame targets the gateway, not the server

What MAC address goes into the Ethernet destination field?

After route selection, the host resolves the selected IPv4 next hop with ARP on the local link. The outgoing frame uses the gateway’s MAC; the IP packet still names 203.0.113.80.

Boundary: This is IPv4 over Ethernet. IPv6 uses Neighbor Discovery instead of ARP.

Failure state: The route exists but the gateway cannot be resolved on this link, so the first frame cannot be sent to that next hop.

05 / MAKE A DECISION

Forwarding chooses the most specific route

Why does this destination use a specific gateway?

The deliberately overlapping route table selects 203.0.113.64/26 for 203.0.113.80. That beats 203.0.113.0/24 and the default route. Only then does the host resolve the selected next hop’s link address.

Boundary: NAT is a separate transformation at a configured edge. It is not performed by every router, and the translation state depends on that device.

Failure state: If all matching routes, including the default, are removed, the host stops before neighbor resolution.

06 / TRANSPORT ENDPOINTS

TCP establishes a connection before application data

What does TCP add to this HTTPS request?

The client sends SYN, receives SYN-ACK, and returns ACK before exchanging stream data. TCP numbers bytes and acknowledges delivery; UDP carries independent datagrams without a transport handshake.

Boundary: This is a simplified three-way handshake. TLS begins after transport setup, and modern clients may choose QUIC over UDP for some HTTPS traffic.

Failure state: The client retransmits according to TCP behavior; a route or policy problem can leave it waiting before application data is exchanged.

07 / TRANSPORT ENDPOINTS

A five-tuple distinguishes this connection

How does the server know which application endpoint should receive it?

For this TCP flow, protocol, source IP and port, and destination IP and port distinguish the transport conversation. The server needs a listener on the destination address/port; a successful DNS lookup says nothing about that listener.

Boundary: A socket can bind a specific address or a wildcard; operating-system connection tracking and proxying can add additional state.

Failure state: A reachable host can reject a connection when no process is listening on the selected destination port.

08 / MAKE A DECISION

NAT rewrites a tuple at a configured edge

Which fields change when the private client reaches the outside network?

In this source-NAT example, the edge maps 10.20.10.25:51514 to 198.51.100.25:62001. Return traffic uses that mapping to find the private client. The remote destination and its port stay the same in this example.

Boundary: This is an illustrative NAPT mapping, not a universal requirement for IP communication. Both public addresses shown are documentation blocks.

Failure state: Without matching translation state, a later reply cannot be mapped back to this private flow.

09 / DISCOVERY AND POLICY

DNS returns data before transport starts

How did the client learn 203.0.113.80?

The application asks a resolver, which may answer from cache or query the DNS hierarchy. An A record supplies an IPv4 address; TTL bounds how long a cached answer may be reused. The later TCP packet does not pass through DNS.

Boundary: Resolver behavior, search paths, multiple answers, IPv6 AAAA records, and connection reuse can change observed requests.

Failure state: A cached address may continue to be used until its TTL expires even after the authoritative record changes.

10 / DISCOVERY AND POLICY

A firewall evaluates packets at its own boundary

Why can a SYN fail while a later reply is allowed?

A stateful firewall can remember an allowed flow and classify return packets using connection state. A stateless rule set evaluates each packet independently. Policy order, direction, and location determine where a packet first fails.

Boundary: Different firewalls implement state and timeout behavior differently. A silent drop and an active rejection produce different client evidence.

Failure state: A silent drop leaves the client waiting in SYN-SENT; the server may see no request at all.

11 / DISCOVERY AND POLICY

Load balancing chooses an endpoint using different evidence

What can a transport balancer know that an HTTP balancer cannot—and vice versa?

An L4 balancer can use addresses, ports, protocol and connection state. An L7 HTTP balancer can inspect application attributes such as host and path once it terminates or parses that protocol. Both need healthy eligible targets.

Boundary: Products vary in TLS handling, source-IP preservation, connection reuse, and health-check implementation.

Failure state: The balancer can receive the request but has no eligible backend to send it to.

12 / OPERATE THE PATH

Troubleshoot the first checkpoint that fails

Where should you look when a request times out?

Test a claim at each layer: name resolution, route, neighbor reachability, TCP handshake, policy, then application response. A later test cannot repair an earlier missing prerequisite.

Boundary: ICMP behavior and firewall policy vary, so a failed ping does not by itself prove TCP is blocked.

Failure state: The packet reaches the policy boundary, which silently drops the SYN. The client remains in SYN-SENT until its timeout.
