AWS Networking Deep Dive

VPC Packet Flow & Architecture

An interactive masterclass into AWS VPC routing internals — from single-subnet kernel interfaces, stateful Security Groups vs stateless NACLs, to Cross-VPC Peering, Transit Gateway route domains, and Inter-Region global backbones.

🌐 The VPC Substrate & Core Primitives
How the AWS Nitro System and Mapping Service abstract physical Clos spine-leaf data centers into logical software-defined overlays.
Nitro Hypervisor ⚡
Virtual Network Substrate
VPCs do not use VLANs. The AWS Nitro System intercepts every packet from the guest OS at the PCIe level, encapsulating it into a Geneve/VXLAN overlay tunnel across the physical Clos fabric.
Directory Service 🗺️
AWS Mapping Service
A hyper-scaled distributed directory that translates logical (VPC-ID, 10.0.1.5) pairs into physical hypervisor rack coordinates and underlay IPs in sub-microsecond latency.
Interface 🔌
Elastic Network Interfaces (ENI)
Virtual network cards bound to an EC2 instance. Holds primary private IPv4, secondary IPs, IPv6 addresses, MAC address, and references Security Groups evaluated in hardware.
The 5 Reserved IP Addresses in Every Subnet

For any subnet CIDR block (e.g. 10.0.1.0/24 with 256 addresses), AWS reserves the first 4 and the last 1 address, leaving 251 usable IPs:

IP Offset Sample IP Name / Role Description
.0 10.0.1.0 Network Address Base address of the subnet CIDR. Cannot be assigned to any interface.
.1 10.0.1.1 VPC Router (Default Gateway) Virtual gateway interface handling all subnet egress and longest-prefix route table matching.
.2 10.0.1.2 Amazon Route 53 Resolver Amazon Provided DNS (Base IP + 2). Resolves internal VPC private DNS and external domains.
.3 10.0.1.3 AWS Reserved Reserved by AWS for future internal infrastructure functionality.
.255 10.0.1.255 Broadcast Address Standard IPv4 broadcast. Broadcast traffic is not supported or transmitted in AWS VPCs.
💡
AZ Mapping Insight: Availability Zone names like us-east-1a are randomly mapped across different AWS accounts to avoid resource hot-spotting. To ensure two accounts are in the same physical facility, compare the immutable AZ ID (e.g., use1-az1).
🚪 Subnet Ingress & Egress (IGW, NAT GW & EIGW)
How public and private traffic enters and exits VPC subnets without single points of failure.
Stateless 1:1 NAT 🌍
Internet Gateway (IGW)
A horizontally scaled software component. The EC2 instance's OS interface (eth0) never knows its public IPv4. The IGW statelessly translates between private IP (10.0.1.5) and Public/Elastic IP (54.210.10.5).
Stateful SNAT 🔄
NAT Gateway (NAT GW)
Deploys in a public subnet to allow private instances outbound internet access while blocking inbound connection attempts. Performs Source NAT (SNAT) and manages ephemeral port pool allocations (1024-65535).
IPv6 Egress 🛡️
Egress-Only IGW (EIGW)
IPv6 uses globally unique addresses without private RFC 1918 NAT. EIGW provides stateful firewalling: outbound IPv6 traffic is tracked and allowed, but unsolicited inbound internet connections are blocked.
Public vs Private Subnet Architecture Flow
1
Public Subnet Ingress / Egress via IGW
Subnet route table has 0.0.0.0/0 ➔ igw-xxxx. Inbound traffic from internet arrives at IGW, gets 1:1 NAT translated to the private IP, and passes through Subnet NACL and Instance Security Group directly.
2
Private Subnet Outbound Request via NAT Gateway
Private EC2 (10.0.2.15:48920) sends request to an external API (140.82.121.4:443). The private route table routes 0.0.0.0/0 ➔ nat-0abc123.
3
NAT Gateway SNAT & Port Translation
NAT Gateway in public subnet receives packet, rewrites Source IP:Port to 52.86.14.99:21045, records translation in its state table, and forwards out through the IGW.
4
Return Response Processing
External API responds to 52.86.14.99:21045. IGW delivers to NAT GW, which matches the state table entry, rewrites destination back to 10.0.2.15:48920, and sends it to the private subnet.
⚠️
NAT Gateway Scale Limit: A single NAT Gateway Elastic IP supports up to 55,000 concurrent connections to a single destination endpoint. High concurrency to a single API can trigger ErrorPortAllocation drops. Fix by attaching secondary EIPs.
🛡️ Stateful Security Groups vs Stateless Network ACLs
Why Security Groups automatically permit return traffic while Network ACLs require explicit ephemeral return port rules.
Stateful Firewall 🔒
Security Group (ENI Level)
Operates at the virtual interface in the Nitro hypervisor. When an inbound packet matches an ALLOW rule, Nitro enters a 5-tuple in the conntrack table. The response packet is automatically allowed out regardless of outbound rules!
Stateless Firewall 🧱
Network ACL (Subnet Boundary)
Operates at the subnet perimeter. Evaluates rules in ascending numerical order (Rule 100 before 200). No connection tracking: every packet (inbound and outbound) must have an explicit matching ALLOW rule.

🚨
The Ephemeral Port Trap: When a browser (e.g. at port 52140) requests your web server on port 443, the server sends response packets back to destination port 52140. If your Subnet NACL Outbound does not allow TCP 1024-65535, the response will be silently dropped by rule *, causing client timeouts!
🔗 VPC Endpoints: Gateway vs Interface PrivateLink
Connect privately to AWS services (S3, DynamoDB, Secrets Manager) without leaving the AWS network fabric.
Route Prefix List 🚪
Gateway Endpoints (S3 & DynamoDB)
Injects managed prefix lists (e.g., pl-63a5400a) into Subnet Route Tables. 100% Free (no hourly charge, no GB fee). Same-region only; cannot be reached over VPN or Direct Connect.
PrivateLink ENI 🔌
Interface Endpoints (AWS PrivateLink)
Provisions dedicated ENIs with private IPs (10.0.1.20) in your subnets. Accessible over VPC Peering, Transit Gateway, and Direct Connect. Private DNS automatically redirects service URLs.

🤝 Cross-VPC Peering & Non-Transitive Routing
Point-to-point direct connectivity over AWS backbone, and the non-transitive edge routing rule.
Line-Rate Backbone ⚡
VPC Peering (pcx-xxxx)
Direct connection between two VPCs. No single point of failure and no bandwidth bottleneck (operates at EC2 line rate). Same-region peering allows referencing remote Security Group IDs.
Critical Constraint 🚫
Non-Transitive Routing
If VPC A is peered with VPC B, and VPC B is peered with VPC C, VPC A cannot reach VPC C through VPC B. AWS blocks edge-to-edge hop routing through intermediate VPCs.
Full Mesh Complexity Formula
# Number of peering connections required for N VPCs Connections = (N * (N - 1)) / 2 # For 10 VPCs in full mesh: (10 * 9) / 2 = 45 peering connections & 90 route table updates
⚠️
CIDR Overlap Rule: VPC Peering strictly requires non-overlapping IPv4/IPv6 CIDR blocks. If VPC A (10.0.0.0/16) and VPC B (10.0.0.0/16) share IP space, peering cannot be established.
🎛️ AWS Transit Gateway (TGW) Hub-and-Spoke
Centralized cloud router scaling multi-VPC architectures with route domains and security inspection.
Centralized Hub ☸️
Hub-and-Spoke Architecture
Replaces complex $N \times (N-1)/2$ peering meshes with a single central router. Scale from 45 peerings down to 10 TGW attachments.
Network Segmentation 🔀
Route Domains (Association vs Propagation)
Maintain separate TGW Route Tables (Prod, Dev, Shared Services). Association controls where a VPC looks up routes; propagation controls which tables receive its CIDR.
Firewall Symmetry 🛡️
TGW Appliance Mode
Guarantees that stateful firewall clusters in an inspection VPC receive both forward and reverse packets in the same AZ, preventing dropped connections from asymmetric routing.
Transit Gateway Route Domain Isolation Example
# Production VPC Attachment Association: TGW-Route-Table-Prod Propagations: TGW-Route-Table-Prod, TGW-Route-Table-Shared # Result: Prod can reach Shared, but CANNOT reach Dev # Development VPC Attachment Association: TGW-Route-Table-Dev Propagations: TGW-Route-Table-Dev, TGW-Route-Table-Shared # Result: Dev can reach Shared, but CANNOT reach Prod
🌍 Cross-Region Peering & AWS Cloud WAN
Global inter-region backbones, encryption at line rate, MTU limits, and automated policy networks.
AWS Global Backbone 🌐
Inter-Region VPC & TGW Peering
Connect VPCs across regions (e.g. us-east-1 to eu-west-1). Traffic never traverses public internet; encrypted at the physical layer with AES-256 MACsec.
MTU Constraint 📦
The MTU 1500 Limit
Intra-region VPC supports Jumbo Frames (9001 bytes MTU). However, Inter-Region Peering strictly enforces MTU 1500. Packets > 1500 bytes with DF bit set are dropped.
Global Orchestrator 🛰️
AWS Cloud WAN
Declarative global network defined by a single JSON policy (core-network-policy.json). Automates multi-region segment routing across global Core Network Edges (CNE).
💰
Cross-Region Data Transfer Pricing: Intra-AZ traffic is free; cross-AZ traffic is ~$0.01/GB; cross-region egress is ~$0.02/GB. Plan multi-region caching and read replicas accordingly.
🏢 Hybrid Connectivity: Direct Connect, DXGW & VPN
Bridging enterprise on-premises data centers with AWS cloud infrastructure.
Dedicated Fiber ⚡
AWS Direct Connect (DX)
Dedicated physical port (1G / 10G / 100G) in a colocation facility. Private VIF connects to single VPC Virtual Private Gateway; Transit VIF connects to Transit Gateway.
Global Router 🌍
Direct Connect Gateway (DXGW)
A global routing abstraction. A single on-premises Direct Connect link attached to a DXGW can access VPCs and Transit Gateways across any AWS region in the world.
IPsec Over Internet 🔒
AWS Site-to-Site VPN
Provisions 2 redundant IPsec tunnels per connection (1.25 Gbps per tunnel limit). Use BGP Equal-Cost Multi-Path (ECMP) to aggregate bandwidth across multiple tunnels up to ~5 Gbps.

🔍 Troubleshooting & Packet Drop Matrix
The top 8 silent network failure modes in AWS VPCs and their exact architectural remediations.
1. Stateless NACL Ephemeral Return Drop
NACL DROP
Cause: Inbound NACL allows port 443, but Outbound NACL lacks rule allowing return traffic to ephemeral ports 1024-65535.
Symptom: Outbound connection from client hangs. TCP SYN reaches EC2 instance, but TCP SYN-ACK is dropped at subnet perimeter.
Fix: Add Outbound NACL Rule: Rule 120 | TCP | Ports 1024-65535 | Allow | 0.0.0.0/0.
2. Asymmetric Route in VPC Peering
ROUTE DROP
Cause: VPC A has route pointing to pcx-123, but VPC B route table has no reverse route for VPC A CIDR.
Symptom: Request arrives at destination EC2, but response packet is routed to VPC B default gateway (IGW/NAT) and blackholed.
Fix: Add reverse static route in VPC B: 10.0.0.0/16 ➔ pcx-123.
3. NAT Gateway Placed in Private Subnet
CONFIG TRAP
Cause: NAT Gateway deployed into a subnet whose route table does NOT have a route to an Internet Gateway (0.0.0.0/0 ➔ igw-xxxx).
Symptom: Private instances route to NAT GW successfully, but NAT GW cannot forward traffic to the internet.
Fix: Always deploy NAT Gateways in a Public Subnet with route table 0.0.0.0/0 ➔ igw-xxxx.
4. Cross-Region Security Group Reference
VALIDATION ERROR
Cause: Attempting to reference sg-xxxx across Inter-Region VPC Peering.
Symptom: AWS API rejects rule or security group rule fails to evaluate. SG referencing only works intra-region.
Fix: Use explicit IP CIDR blocks (e.g. 10.1.0.0/16) in Security Group rules for cross-region peering.
5. Inter-Region Jumbo Frame MTU Blackhole
MTU DROP
Cause: EC2 instances configured for MTU 9001 sending jumbo frames across Inter-Region Peering (enforces MTU 1500).
Symptom: Small ICMP ping packets work, but large HTTPS payloads or file transfers stall indefinitely.
Fix: Set interface MTU to 1500 or ensure ICMP Type 3 Code 4 (Fragmentation Needed) is allowed in NACLs for PMTUD.
6. Asymmetric Firewall Drop in TGW Inspection VPC
TGW ASYMMETRY
Cause: Inter-VPC traffic routed through firewall cluster without TGW Appliance Mode enabled.
Symptom: Forward packet hits Firewall AZ-a; return packet hits Firewall AZ-b. Firewall AZ-b drops return packet as unknown TCP state.
Fix: Enable Appliance Mode: aws ec2 modify-transit-gateway-vpc-attachment --options ApplianceModeSupport=enable.
