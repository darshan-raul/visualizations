## Choose from the requirement

Start with the protocol and the decision you need AWS to make. If the requirement says URL path, hostname, headers, authentication, or WAF, start with ALB. If it says TCP, UDP, QUIC, TLS pass-through, or a fixed address in each Availability Zone, start with NLB.

<DecisionMatrix />

> [!NOTE]
> **A common wrong turn:** choosing NLB because it sounds faster, then discovering that the application needs path routing or WAF. Choose from the protocol and routing requirement first; validate capacity and latency separately.

## Put each service in the path

ALB and NLB are alternative regional application entrances. Global Accelerator can sit in front of either one when clients need stable global addresses and regional failover. GWLB belongs on a route that must pass through a firewall or another virtual appliance.

<BirdseyeArchitecture />

> [!NOTE]
> **Architecture boundary:** GWLB is neither an application frontend nor the firewall. A route sends traffic to a GWLB endpoint, and GWLB selects an appliance. Repeat endpoints and appliances per Availability Zone where the production design requires zonal resilience.

## Use ALB for HTTP routing

Use ALB when one HTTPS entrance must send `/checkout` to one service and `/static` to another, route multiple hostnames, apply AWS WAF, or perform supported authentication and JWT checks. The listener evaluates rules in priority order; the selected target group then chooses a healthy application target.

<AlbRequest />

> [!NOTE]
> **Common misconception:** the target group inspects the URL. **Correct model:** the listener rule selects the target group.

## Use NLB for transport protocols or zonal static IPs

Use NLB for TCP, TLS, UDP, TCP_UDP, QUIC, or TCP_QUIC services; for TLS pass-through; or when allowlists require a stable address per enabled Availability Zone. NLB maps a transport flow without reading an HTTP path. It can also target an ALB directly, or publish a service to interface VPC endpoints through PrivateLink—the arrows and target types matter.

<NlbFlow />

## Use GWLB to insert a firewall fleet

Use GWLB when a route must send traffic through third-party firewalls, intrusion detection, or other GENEVE-capable appliances. The route table points to a zonal endpoint; GWLB selects an appliance and returns allowed traffic to the routed path.

<GwlbStepper />

> [!NOTE]
> **Common misconception:** GWLB replaces the ALB or NLB. **Correct model:** route tables and an endpoint insert an appliance hop; allowed traffic continues toward the application entry.

## Use Global Accelerator for multi-Region entry

Use a standard accelerator when clients need static anycast addresses and new connections should move between healthy regional ALB or NLB endpoints. Global Accelerator chooses the Region and endpoint; the regional load balancer still chooses the application target.

<GaFailover />

> [!NOTE]
> **Common misconception:** a 50% traffic dial means half of all listener traffic, and changing it moves existing connections. **Correct model:** the dial applies to traffic already directed to that endpoint group, and updates affect new connections.

## Check what happens when targets become unhealthy

A failed check changes one selector’s eligible set. It does not prove that the full request path has failed—or recovered.

<HealthMatrix />

## Choose a deployment pattern and test failures

Each extra selector adds a health boundary. Give every service one explicit job, then test what crosses the boundary when it fails.
